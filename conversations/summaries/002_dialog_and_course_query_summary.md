# 對話摘要：002 - 預排課程查詢與彈窗對話盒事件監聽

## 📌 階段概述
在登入成功後，本階段實作「預排課程」的自動抓取，處理 ASP.NET 的回傳表格，並加入使用者主動確認（Y/N）的流程控制機制，徹底解決背景異常問題。

## 🎯 使用者核心訴求
1. **點擊查詢預排**：自動點選 `ContentPlaceHolder1_Button7`（查詢預排課程）。
2. **等待表格呈現**：等待 `<table id="ContentPlaceHolder1_grd_subjs">` 載入完成。
3. **行數回報精確**：在終端機精確告知當前載入了幾筆課程（幾列資料），不能誤報。
4. **人機互動暫停點**：表格讀取完成後暫停，等待使用者在終端機輸入 `Y` 才開始動作；輸入 `N` 則安全退出瀏覽器。

## 🛠️ 關鍵技術決策與架構變更
1. **原生 Dialog 監聽器的生命週期管理**：
   - 由於點擊課程查詢或選課時會跳出原生 JavaScript `alert`，註冊 `page.on("dialog", handle_dialog)`，在擷取訊息內容後自動執行 `dialog.accept()`。
2. **表格渲染時機等待優化**：
   - 增加 `table.locator('tr:has(td)').first.wait_for(...)`，避免 table 元素出現但內部的 td 尚未由 PostBack AJAX 填入的競態條件。
3. **Playwright 安全關閉機制**：
   - 使用者反映在按 `N` 關閉瀏覽器時出現 `SyncBase._sync.<locals>.<lambda>` 異常。透過在關閉 context 與 browser 前取消 page 事件監聽並加上例外保護，確保終端優雅退出。

## ⚠️ 踩坑、阻礙與解決方案
- **問題**：終端顯示表格只有 1 列，但網頁實際有 14 列。
- **原因**：選擇器抓到了 `<tr>` 的包含表頭（th）列，或是資料尚未渲染完畢就提早計算 count。
- **解法**：嚴格限定選擇器為 `tr:has(td)`，並在點擊後加上緩衝時間與 `networkidle` 等待。

## 📊 產出產物與成果
- 完善 `auto_login.py` 中預排課程查詢與表格等待區塊。
- 建立安全的使用者終端輸入交互（Y: 繼續 / N: 退出）。
