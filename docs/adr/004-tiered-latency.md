# ADR-004：人性化雙軌隨機微延遲 (Tiered Latency) 策略

- **狀態**：Accepted
- **日期**：2026-06-03
- **Agent**：`system`
- **任務**：`TASK-006`

## 1. 背景與問題

延遲過長（> 0.5s）會失去搶課優勢；完全零延遲則可能引發高頻封包被伺服器誤判為 DoS 攻擊或吞噬 ASP.NET PostBack。

## 2. 評估過的方案

| 方案 | 優點 | 缺點 |
|---|---|---|
| 固定長延遲 (>0.5s) | 安全、不易出錯 | 失去秒級搶課優勢 |
| 零延遲衝刺 (0s) | 理論速度最快 | 易觸發伺服器阻擋、PostBack 狀態競爭引發崩潰 |
| 雙軌階梯微延遲 | 查詢階段穩健、搶課階段極速，兼顧成功率與安全性 | 需要針對不同階段調整參數 |

## 3. 決策與理由

- **階段 1 (Query Phase)**：150ms 延遲，求穩，確保表格與人數對話盒完全就緒。
- **階段 2 (Rush Phase)**：20ms ~ 50ms 隨機微延遲，模擬電競選手極限手速特徵。

## 4. 影響與代價

- 搶課速度達到秒級加選，同時保持連線協議之穩定性。
