# ADR-002：採用非無頭 (Headed) 原生 Chrome 實體

- **狀態**：Accepted
- **日期**：2026-06-02
- **Agent**：`system`
- **任務**：`TASK-006`

## 1. 背景與問題

選課關乎學分與畢業資格，使用者需要極高的掌控感，不可完全處於 Headless 黑箱狀態。
此外，學校伺服器對無頭 Chromium 可能具備基礎特徵識別與反爬蟲阻擋。

## 2. 評估過的方案

| 方案 | 優點 | 缺點 |
|---|---|---|
| Headless 模式 | 資源佔用較少 | 無法直觀監控、遭遇驗證碼時無法人工介入、易遭特徵阻擋 |
| Headed Chrome 實體 | 可親眼見證操作、隨時可手動接手、特徵接近真人瀏覽器 | 需消耗本機圖形介面資源 |

## 3. 決策與理由

使用 `browser = p.chromium.launch(headless=False, channel="chrome")`。

## 4. 影響與代價

- 使用者能親眼見證登入與頁面切換狀態。
- 萬一遭遇驗證碼或緊急狀況，使用者隨時能無縫接手瀏覽器手動操作。
