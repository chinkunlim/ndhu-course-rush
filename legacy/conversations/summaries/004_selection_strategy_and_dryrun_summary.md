# 對話摘要：004 - 自訂選課優先級策略與離峰空轉預演

## 📌 階段概述
本階段實現了多種選課策略模式（預設順序 vs Markdown 自訂順序），並解決了在「非選課時段（按鈕尚未開啟）」進行測試與演練（Dry-run）的關鍵問題。

## 🎯 使用者核心訴求
1. **三種搶課模式選單**：
   - 輸入 `Y`：按照網頁原始預設順序全自動點擊。
   - 輸入 `2`：讀取使用者編輯後的 `courses_info.md` 中的順序搶課。
   - 輸入 `N`：取消並關閉瀏覽器。
2. **解析 Markdown 自訂順序**：
   - 解析數字優先級（0 最優先，或 1, 2, 3... 升序排列），未填寫者自動忽略。
3. **離峰演練（Dry-run）支援**：
   - 在選課系統尚未開放時，第一個欄位是空白的（加選按鈕尚未出現）。程式必須能夠檢測到「無按鈕」並跳過，不可造成拋錯崩潰。

## 🛠️ 關鍵技術決策與架構變更
1. **穩健的 Markdown 欄位正則解析器**：
   - 支援讀取 `| 0 | **0** | ...`，解析第一欄的自訂順序，相容純數字或粗體字形，並與第二欄的原行號（Index）綁定。
2. **安全按鈕探測機制**：
   - 點擊前檢查按鈕 locator 是否存在且 visible，若無按鈕則印出警告並快速跳至下一科，實現優雅的演練機制。
3. **終端機輸出與速度權衡**：
   - 評估在終端機輸出文字是否會拖慢點擊速度。結論為：print 本身耗時極微（< 0.1ms），但過度冗長的日誌會降低流暢度，因此保留精簡清楚的狀態提示即可。

## ⚠️ 踩坑、阻礙與解決方案
- **問題**：使用者在非選課時間測試時，所有按鈕均未出現，程式原本可能報錯找不到按鈕。
- **解法**：加入防護判斷，無按鈕時印出 `⚠️ 編號 [X] 沒有可點擊的加選按鈕，跳過。`，順暢完成全流程預演。

## 📊 產出產物與成果
- 實作完整解析 `courses_info.md` 優先級演算法。
- 建立具備乾跑演練能力的搶課迴圈。
